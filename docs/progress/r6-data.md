# R6 data (the civilization builder lane, widened to the data side)

The lane's state, as the other lanes' files in this folder. Each round rewrites this file to the current state; the
rounds' stories go in PORT_LEARNINGS.md ("R6 data, round 1", "R6 data, round 2"). The civilization builder's own
rounds 1-2 are in `r6-civilization-builder.md`.

**Done**
- Round 1 (`rust-data1`): the language strings (ee_util `language_strings.rs`, generated by `tools/lang_strings.py`)
  and the `.rmv` reader (ee_rmap `rmv.rs`; `Unit10.cpp` deleted). Gates: `rmap_gate.py check` and `check --reader`.
- Round 2 (`rust-data2`):
  - The data gate reads records defined in Rust (`tools/eedata/overlay.py` `RUST_STRUCTS`, `specgen.py`): the five
    UI records ee_ui owns and the nine db records below. `eedata check` and `cppgate` PASS again on rust.
  - The random map's game passes (ee_rmap `game.rs`): the water points and space fill, the smoothing, the heights onto
    the mesh, the painting with the ambient units, the feature claims, the start units, walls and herds, the resource
    objects, the players-connected test, the grid size and rings. `EERandomMap.cpp` keeps the PIM steps, the
    generator list, `InitializeValues`, `CreateValidMap`, `CreateTeams`, `PlaceWall` and the host (1,370 -> 858
    lines; `ee/EERandomMapView.h` the state's view). The rmap gate runs the Rust water points, claims and rings.
  - The db table records and their copies (ee_data `tables.rs`): dbanimals, dbunitbehavior, dbweapontohit,
    dbstartingresources, dbupgrade, dbcolortable, dbaiunittargeting, dbterraintype, dbgamevariant. The classes'
    plain members are the Rust `EeData*Fields` (their base); `ee/EEDbRecords.h` is the loaders' common read.

**Gates of this lane**: `eedata.py check` and `cppgate` (the records' layouts and every table's text), the rmap gate
(`tools/rmap_gate/rmap_gate.py check`, `check --reader`), the oracle and the random map captures (the game passes and
the tables are simulation input).

**Measure of the rest** (lines on rust-data2):
- `Database/`: EETerrainTable 419 (two records, the mesh texture loads), EEButtonObject 307, EERules 216,
  EEDataTextFile 183, EETerrainTypeTable's damage tables, EETerrainColorTable 89, EEDatabase/EEDbObject (the unit
  class records), EECPBehaviorTable, EERandomMapTable.
- `Data Pre-Loading Thread/` 2,094 (EEGraphicObject 1,049 with the model part scans, EEGraphicEffect, EEMusicObject,
  EESoundObject, EEDataPreLoading): render and sound side, reached only by the tour; their records
  (EEGraphicObjectRecord, EESoundRecord, ...) can move to `tables.rs` the same way first.
- `EERandomMap.cpp` 858: `Initialize` (the generator list from the `.rmv` files: a reader host like `rmv.rs`'s),
  `InitializeValues` (the name lists), `PlaceWall` (the wall pieces are EEFOFindNewTargetNearOldTarget.cpp's).
- `Empire Earth/EECivilization.cpp` 325 (a thin client of the civilization manager, which is Rust);
  `FillCivilizationList`.
